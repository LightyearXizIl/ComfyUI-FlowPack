# ComfyUI FlowPack：功能、技术栈与界面设计实施计划

## 一、产品定位与总体架构

**软件名称：ComfyUI FlowPack**  
**简称：FlowPack**  
**定位：ComfyUI 工作流资源安装与打包工具**  
**宣传语：工作流、节点、模型，一键安装，轻松打包。**

首版面向 Windows x64 上的官方 ComfyUI Desktop，同时服务资源包使用者与创作者。支持在线清单、离线包、一键安装、依赖检查、可视化打包和资源维护。

核心约束：

- 软件本体与模型、节点、工作流等资源分离。
- 不附带 Desktop、ComfyUI 核心、ComfyUI Python 环境或显卡驱动；提供[官方下载入口](https://comfy.org/download)。
- 模型集中共享，节点和 Python 依赖按目标实例部署。
- 默认保护用户现有环境，涉及替换已有 Python 依赖时暂停安装。
- 所有用户均可制作和分享资源包。
- 界面采用**现代简洁工具风**，支持软件内调整外观及导入、导出主题 JSON。

架构分为三部分：

| 部分 | 管理内容 | 生命周期 |
|---|---|---|
| FlowPack 软件 | 界面、安装引擎、解析器、适配器、自身运行库 | 独立安装和升级 |
| 外部资源库 | 模型、节点归档、工作流、素材、资源包、缓存、安装记录 | 不随软件升级或卸载删除 |
| ComfyUI 实例 | 已部署节点、Python 依赖、工作流副本、外部路径配置 | 按实例检查和维护 |

首版不建设商城、账号系统、云端生成、任意页面拖拽编辑器或每个工作流独立运行环境。

## 二、技术栈与模块划分

### 技术选型

| 层次 | 采用技术 | 用途 |
|---|---|---|
| 语言与框架 | C#＋.NET 10 | 应用及安装引擎 |
| 桌面界面 | WPF＋XAML | 原生 Windows 界面 |
| 界面架构 | MVVM＋CommunityToolkit.Mvvm | 分离界面状态和业务逻辑 |
| 主题系统 | ResourceDictionary＋DynamicResource＋统一控件模板 | 集中样式管理、运行时换肤 |
| 主题文件 | JSON＋System.Text.Json | 外观设置、主题导入导出 |
| 服务组织 | Microsoft.Extensions.DependencyInjection、Logging | 依赖注入与日志 |
| 执行进程 | 独立 `FlowPack.Worker.exe` | 下载、校验、解包、部署 |
| 进程通信 | Windows Named Pipes＋JSON | 任务命令、进度、结果 |
| 数据库 | SQLite＋Microsoft.Data.Sqlite | 资源索引、引用、任务及安装记录 |
| YAML | YamlDotNet | ComfyUI 路径配置 |
| 下载 | HttpClient | 流式下载、续传、代理、鉴权 |
| 哈希 | SHA-256 | 完整性校验和重复资源识别 |
| 归档 | System.IO.Compression，ZIP64 | 离线包导入导出 |
| 环境调用 | System.Diagnostics.Process | 执行目标 Python、pip |
| ComfyUI 通信 | 本地 HTTP＋ClientWebSocket | 系统信息、节点信息、测试任务 |
| 凭据 | Windows Credential Manager | 保存下载令牌 |
| 测试 | MSTest＋`dotnet test` | 单元与集成测试 |
| 发布 | .NET 自包含发布＋Inno Setup | Windows 安装程序 |
| 持续集成 | GitHub Actions Windows Runner | 构建、测试、发布产物 |

WPF 的动态资源适合运行时更新主题，控件模板用于集中定义控件外观。[动态资源说明](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/systems/xaml-resources-overview)、[样式与模板](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/controls/styles-templates-overview)

FlowPack 自包含发布携带自身 .NET 运行库，用户无需额外安装 .NET；该运行库属于软件本体。[发布说明](https://learn.microsoft.com/en-us/dotnet/core/deploying/)

### 模块边界

| 模块 | 职责 |
|---|---|
| `FlowPack.App` | 页面、导航、ViewModel 和使用流程 |
| `FlowPack.DesignSystem` | 主题参数、控件样式、图标、字体、统一布局组件 |
| `FlowPack.Core` | 包模型、依赖关系、安装规划和所有权规则 |
| `FlowPack.Infrastructure` | 数据库、文件、下载、归档、凭据和日志 |
| `FlowPack.ComfyUI` | 环境发现、工作流解析、路径接入、本地接口 |
| `FlowPack.Worker` | 任务执行、进度持久化和中断恢复 |
| `FlowPack.Tests` | 业务、安装、主题和集成测试 |

界面不直接修改 ComfyUI，由 Worker 执行。一个资源库只允许一个 Worker 写数据库；同一实例的部署串行执行，下载可并行。

首版资源库支持本机 NTFS／exFAT 磁盘，不支持多设备同时写入网络共享库。依赖版本和 SDK 使用锁定文件固定。

发布主程序为 `ComfyUI.FlowPack.exe`，采用 `win-x64` 自包含目录发布，不启用裁剪或 Native AOT。安装器只管理软件文件，资源库与用户主题不作为卸载删除对象。

## 三、界面美化与易修改方案

### 1. 视觉方向

采用现代 Windows 工具界面：清晰分区、适度留白、柔和圆角、统一图标和明确的操作层级。

默认设计：

| 项目 | 默认方案 |
|---|---|
| 明暗模式 | 跟随系统，可切换浅色、深色 |
| 强调色 | 蓝色，可在外观设置修改 |
| 字体 | Segoe UI，中文使用 Microsoft YaHei UI 回退 |
| 正文字号 | 14 DIP |
| 间距 | 以 4、8、12、16、24 DIP 为基础 |
| 圆角 | 按钮和输入框 6 DIP，卡片 10 DIP |
| 默认窗口 | 1280×800 DIP，受当前屏幕工作区限制 |
| 最小窗口 | 960×640 DIP |
| 动画 | 约 150 毫秒的轻量过渡，可关闭 |
| 图标 | 集中维护的矢量 DrawingImage，不使用表情符号代替图标 |

颜色区分成功、警告和失败，同时配合图标、文字说明，避免只靠颜色表达状态。

### 2. 页面布局

采用**左侧导航＋顶部操作区＋中央内容区＋按需详情面板**。

| 页面 | 视觉与交互设计 |
|---|---|
| 首页 | 当前环境状态、导入资源包、创建资源包、最近任务；避免堆积无用统计 |
| 我的资源包 | 封面卡片与列表切换，搜索、状态筛选、版本及安装状态 |
| 包详情 | 说明、依赖、兼容性、体积和验证等级，安装按钮位置固定 |
| 工作流 | 名称、说明、预览图和依赖摘要；首版不制作节点画布 |
| 模型库 | 默认列表，便于比较类型、大小、路径及引用 |
| 节点管理 | 名称、版本、来源、加载状态，冲突时展开具体信息 |
| 打包向导 | 左侧步骤，中央编辑，底部上一步、下一步和导出 |
| 任务中心 | 阶段、进度、速度、剩余量，错误说明与重试入口 |
| 设置 | 环境、资源库、下载、外观、诊断分组 |

详情面板在窄窗口中改为独立详情页。弹窗仅用于必须立即处理的事项；一般进度和提示在页面内展示。

首次使用、空列表、加载中、下载失败、缺少 Desktop、资源库离线等状态都需要完整设计，不只美化有数据时的页面。

### 3. “很好改”的实现方式

外观拆成四层：

| 层次 | 内容 | 修改方式 |
|---|---|---|
| 主题参数 | 颜色、字号、圆角、密度、动画 | 设置页面或 JSON，立即预览 |
| 控件样式 | 按钮、输入框、表格、卡片、标签、弹窗 | 集中修改 XAML 样式和模板 |
| 页面布局 | 导航、分栏、卡片排列、向导结构 | 修改对应页面 XAML |
| 业务逻辑 | 安装、下载、依赖分析、打包 | 独立服务，不参与外观修改 |

**换配色和尺寸不需要重新编译；调整页面结构需要修改 XAML 并重新构建，但不应改动安装业务。**

具体实现：

- 页面不直接写品牌颜色或重复定义圆角、字号和阴影。
- 使用语义化参数，例如背景、卡片、主文字、次文字、边框、强调色、错误色。
- 可动态调整的参数使用 `DynamicResource`；固定图标和不变资源使用 `StaticResource`。
- 按钮、资源卡片、状态标签、空状态、任务进度和错误面板使用统一组件。
- 控件样式集中在 `FlowPack.DesignSystem`，禁止各页面复制一份按钮模板。
- 提供开发用“组件预览页”，一次检查所有控件及悬停、禁用、焦点、错误等状态。

### 4. 用户外观设置与主题文件

“设置 → 外观”提供：

- 浅色、深色、跟随系统。
- 强调色和主要界面颜色。
- 正文字号：12–20 DIP，其他字号按比例生成。
- 圆角：0–16 DIP。
- 舒适／紧凑两种密度。
- 开关界面动画。
- 实时预览、应用、取消、恢复默认。
- 导入及导出 `.flowpack-theme.json`。

主题文件包含格式版本、主题名称、浅色／深色基底和允许覆盖的参数，不包含脚本、远程资源或任意 XAML。

实现规则：

- 内置主题随程序发布；用户主题存放于用户配置目录，与模型资源库分开。
- 主题导入后先检查类型、数值范围和必需的颜色组合，再进入预览。
- 正文与背景对比度低于 4.5:1 时提示具体组合并阻止应用。
- 取消预览恢复原主题；文件损坏时保留当前主题，启动加载失败则使用内置主题。
- 外部修改主题文件后，通过“重新加载主题”应用；首版不监控文件变化自动刷新。
- 主题切换只更新界面，不重启 Worker，不中断下载和安装。
- 系统高对比度模式优先使用系统颜色，保留可见键盘焦点。

主题设置是软件的外观配置，不与 ComfyUI 模型、工作流资源包混在一起。

### 5. 界面质量要求

- 支持 Windows 缩放与多显示器 DPI 切换。
- 长路径可截断显示，并提供复制和完整查看入口。
- 大列表启用虚拟化，封面按需加载。
- 下载及日志刷新节流，不让高频进度事件卡住界面。
- 支持键盘导航、明确的焦点和可访问名称。
- 任务运行期间换主题、字号或密度，不丢失选择、筛选和进度。

## 四、资源规范与核心功能

### 1. 资源库和部署

资源库包含模型、节点版本归档、工作流原件、输入素材、包清单、缓存、数据库和备份。

首次选择位置时，拒绝放入 FlowPack 安装目录或 Desktop 程序资源目录。

部署方式：

- 模型通过外部搜索路径共享加载。
- 节点从资源库归档复制到目标实例用户节点目录。
- Python 依赖安装到目标实例已确认的环境。
- 工作流和素材部署副本，保留资源库原件。
- 配置修改前备份，只更新 FlowPack 管理的条目，保留其他配置。
- 生成结果继续由 ComfyUI 管理，默认不打包。

Desktop 的外部路径配置与节点依赖安装分别处理，不修改其程序资源目录。[官方说明](https://docs.comfy.org/installation/desktop/windows)

### 2. 包格式

| 格式 | 内容 |
|---|---|
| `.cpack.json` | 在线清单，声明下载来源、版本、大小、哈希和部署用途 |
| `.cpack` | ZIP64 离线包，包含清单和已收集资源 |

同时支持展开目录。大模型不压缩存储，首版不实现自定义分卷。

清单记录包身份、兼容条件、工作流入口、节点精确版本、模型和素材、Python 锁定依赖、分发信息及验证等级。包内使用相对路径，不包含本机凭据。

工作流支持官方 v0.4、v1.0 JSON，保留未知字段。[工作流规范](https://docs.comfy.org/specs/workflow_json)

### 3. 一键安装

流程为：

**导入 → 环境检查 → 安装预览 → 下载校验 → 锁定实例 → 部署 → 验证 → 保存记录。**

- 自动发现候选实例，交叉确认目录、Python、用户目录及服务地址。
- 预览显示复用、新增、下载、冲突及各磁盘峰值空间。
- 支持代理、续传和重试，资源校验通过后才进入正式库。
- 部署时目标 ComfyUI 必须停止，有运行任务时等待，不强制结束。
- 同名模型内容相同则复用，内容不同则阻止覆盖。
- 节点有本地修改或归属其他工具时，不自动覆盖。
- Python 依赖需要替换已有版本时，在修改前停止。
- 首版自动安装支持可解析的兼容 wheels；源码编译和自定义安装脚本需要专门适配。
- 环境发生变化时重新规划，不直接执行旧计划。

### 4. 打包向导

步骤为：

**选择工作流 → 分析依赖 → 补全信息 → 选择交付方式 → 完整性检查 → 导出。**

依赖分析结合工作流元数据、Registry、当前实例和已支持的解析规则；动态依赖提供人工补充。

必需项未解决时允许保存草稿，不能标记为完整可安装包。离线包必须收集目标环境需要的 wheels；缺少文件、存在远程 API 或运行时下载时明确标记联网需求。

无法确认可再分发的资源默认仅保留获取信息。不直接压缩整个 ComfyUI 环境。

### 5. 验证与维护

验证分为四级：

1. 文件齐备且哈希通过。
2. 环境检查通过，节点加载、模型可见。
3. 工作流静态检查通过。
4. 用户主动试运行并产生预期输出。

只完成检查时不显示生成成功。

维护功能包括修复、任务恢复、包升级、卸载、资源清理和资源库迁移：

- 文件操作前记录日志，崩溃后结合实际文件状态恢复。
- 恢复受管文件和配置，不承诺第三方代码副作用完全可回滚。
- 卸载释放引用，只删除本软件部署、无人引用且未修改的节点和工作流。
- 模型和 Python 依赖默认保留；清理模型由用户选择。
- 迁移先复制和校验，更新路径成功后保留旧库供用户处理。
- Desktop 环境变化后，旧验证结果标记为需复检。
- 软件升级前备份数据库，不重置资源库和用户主题。

## 五、接口、开发顺序与验收

### 核心接口

| 接口 | 职责 |
|---|---|
| `InspectInstance` | 获取实例目录、环境指纹和能力 |
| `AnalyzeWorkflow` | 提取依赖和待补全项目 |
| `PlanInstall` | 生成动作、空间需求和冲突，不修改环境 |
| `ExecuteInstall` | 执行已确认计划并返回进度 |
| `BuildPackage` | 导出清单或离线包 |
| `VerifyInstallation` | 返回分级检查报告 |
| `RemovePackage` | 按引用和所有权卸载 |
| `PreviewTheme` | 校验主题并临时应用 |
| `ApplyTheme` | 保存主题设置并广播界面更新 |
| `CancelThemePreview` | 恢复预览前的主题 |
| `ImportTheme`／`ExportTheme` | 读写版本化主题 JSON |

核心类型包括包清单、资源条目、环境指纹、安装计划、安装记录、验证报告及 `ThemeDefinition`。清单和主题均有独立格式版本，不与软件版本绑定。

### 开发顺序

1. **界面基础与视觉样板**  
   先完成设计系统、明暗主题、组件预览页，以及首页、资源包列表、任务中心三个样板页面；样板使用明确的模拟数据，不表示安装功能完成。

2. **安装闭环**  
   接入环境识别、资源库、下载、安装规划、节点部署和验证，用真实状态替换模拟数据。

3. **分享与外观定制**  
   完成打包向导、在线清单、离线包、外观设置和主题导入导出。

4. **维护与正式发布**  
   完成任务恢复、升级、卸载、迁移、诊断、安装包和发布验证。

### 验收标准

**功能验收**

- 多实例及中文、空格路径下绑定正确，不修改其他环境。
- 相同模型复用，同名不同内容不覆盖。
- 依赖替换在修改前被阻止。
- 大于 4 GB 的模型正确打包、解包和校验。
- 中断、磁盘不足、崩溃后不将半成品登记为成功。
- 卸载一个包不破坏其他包共享的资源。
- 完整离线包在满足前置条件的断网环境中安装通过。
- 软件升级、卸载和重新安装后资源与用户主题可保留、恢复关联。
- 文件检查、静态检查和实际生成结果区分准确。

**界面验收**

- 明暗主题覆盖全部页面、弹窗和控件状态。
- 修改强调色、字号、圆角和密度，全局即时生效。
- 主题导出后重新导入，受支持参数一致。
- 无效主题不导致启动失败，取消预览能恢复原样。
- 100%、150%、200% 缩放及最小窗口下，主要操作可见可用。
- 长中文名称、长路径、空状态、失败状态没有遮挡或溢出。
- 大列表和下载过程中界面可响应，换肤不影响任务。
- 新页面复用设计系统，无需重新编写一套控件样式。

首版正式支持范围以实际完成端到端测试的 Windows Desktop 环境组合为准；未知环境可检查和打包，暂停自动部署。
