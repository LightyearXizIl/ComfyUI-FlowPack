## 如何维护

1. 改用户操作时同步使用指南；改模块职责或数据格式时同步架构说明。
2. 改脚本、运行或验证命令时同步开发指南。
3. 新交付或验收结果更新项目状态，注明日期、源码/产物范围及证据路径；详细过程放专项记录。
4. 历史记录保留原事实，不把当时的“最新”“待验证”当作当前结论。交接页顶部链接当前状态。
5. 把“代码已实现”“测试通过”“包已生成”“实际安装/推理通过”“已远程发布”分别记录。跳过项仍为待验证。

`artifacts/acceptance/`、便携包、运行数据与构建输出没有纳入 Git。文档中的这些路径是本机证据位置，其他电脑需生成自己的产物；缺失证据时不能据文字认定重新验收通过。
